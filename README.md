# Gini-ICCS Longitudinal Project

This repository builds a harmonized student-level pooled database from CivED/ICCS studies and links country-year inequality from SWIID.

The project is organized so new users can:

1. Understand where raw data are located.
2. Re-run processing from raw files.
3. Inspect a transparent variable mapping/codebook.
4. Validate final data quality with a Quarto report.

## What This Project Produces

Main final output:

- `proc/output/pooled_data.rds`

This file contains pooled student-level data across study waves and includes `study` so users can analyze by year.

## Repository Map

### Core Data Pipeline

- `proc/00-run-proc.R`
  - Main runner script.
  - Executes full processing workflow and writes outputs to `proc/output/`.

- `proc/01-build-cived-1999.R`
  - Builds CivED 1999 dataset from raw Grade 8 files (`bs_*.sav`).
  - Harmonizes IDs, participation items, education, gender, civic score, and weights.

- `proc/02-build-iccs-2009.R`
  - Builds ICCS 2009 dataset from raw ISG files (`ISG***C2.sav`).
  - Applies harmonization to the final schema fields.

- `proc/03-build-iccs-2016.R`
  - Builds ICCS 2016 dataset from raw ISG files (`ISG***C3.sav`).
  - Applies harmonization to the final schema fields.

- `proc/04-build-iccs-2022.R`
  - Builds ICCS 2022 dataset from raw ISG `.Rdata` files.
  - Selects one form per country, preferring `C4` over `B4`.

- `proc/05-build-pooled-data.R`
  - Binds all wave-level processed files.
  - Joins SWIID gini by normalized country label and study year.
  - Writes final pooled output.

- `proc/06-codebook.R`
  - Generates documentation files in `documents/`.
  - Exports final schema and mapping table.

- `proc/07-validate-items-against-raw.R`
  - Independent check of every participation item (wave × country file) against the raw IEA value-label text.
  - Writes `documents/item_validation.csv`; all checks must report 0 mismatches.

### Documentation and Validation

- `documents/codebook_final_schema.csv`
  - Final field dictionary (name, type, description).

- `documents/codebook_mapping_table.csv`
  - Study-by-study mapping from raw variable names to harmonized variables.

- `documents/codebook.md`
  - Human-readable summary of key codebook decisions.

- `report/01-processing-validation.qmd`
  - Quarto validation report script.
  - Includes dimensions, country coverage, distributions, and missingness checks.

- `report/01-processing-validation.html`
  - Rendered HTML report.

### Data Storage

- `raw_data/`
  - Raw source files (not generated by scripts).
  - Contains the study inputs and SWIID data used for linking.

- `proc/output/`
  - Generated processing outputs.
  - Contains per-wave files and final pooled dataset.

### Other Project Areas

- `analyses/`: analysis scripts and model outputs.
- `presentations/`: presentation source files and assets.
- `article/`: manuscript drafting material.
- `bib/`: bibliography files.
- `2022_INVALSI/`: legacy/original project materials, including historical Stata workflow references.

## Analyses Reports

The analyses area hosts visualizations, statistical analyses, and models:

- `analyses/items_descriptions.qmd` / `.html`: descriptive analysis of dichotomized participation items.
  - `https://nicolastobarj.github.io/gini-iccs/analyses/items_descriptions.html`
- `analyses/01-confirmatory-models.R`: estimates the preregistered models (WeMix weighted + lmer), the prespecified country-wave robustness model and wave-by-wave models. Writes `analyses/output/confirmatory_models.rds`.
- `analyses/02-reconciliation-invalsi.R`: step-by-step comparison with the INVALSI 2022 Stata specification. Writes `analyses/output/reconciliation.rds`.
- `analyses/01-confirmatory-models.qmd` / `.html`: results report (tables + figures; PNGs in `analyses/figures/`).
  - `https://nicolastobarj.github.io/gini-iccs/analyses/01-confirmatory-models.html`

Run order (from project root): `Rscript analyses/01-confirmatory-models.R`, `Rscript analyses/02-reconciliation-invalsi.R`, then `quarto render analyses/01-confirmatory-models.qmd`.

## How to Run the Project

## 1) Run full processing

From project root in R:

`source("proc/00-run-proc.R")`

Or in terminal:

`Rscript proc/00-run-proc.R`

Main outputs:

- `proc/output/cived_1999_raw_processed.rds`
- `proc/output/iccs_2009_raw_processed.rds`
- `proc/output/iccs_2016_raw_processed.rds`
- `proc/output/iccs_2022_raw_processed.rds`
- `proc/output/pooled_data.rds`

## 2) Regenerate codebook files

`Rscript proc/06-codebook.R`

Generated files:

- `documents/codebook_final_schema.csv`
- `documents/codebook_mapping_table.csv`
- `documents/codebook.md`

## 3) Render processing validation report

`quarto render report/01-processing-validation.qmd`

Generated file:

- `report/01-processing-validation.html`

## Important Processing Conventions

- The processing is raw-first: scripts read original files from `raw_data/`.
- Country labels can be recovered from file code fallbacks where SPSS/R labels are absent.
- SWIID gini is matched by normalized country label and study year.
- Participation items are harmonized to 1 = certainly not ... 4 = certainly would do in all waves (ICCS 2009/2016/2022 raw items are reversed, 5 - x).
- Non-substantive codes (CivED 0/8; ICCS 7/8/9) are harmonized to `NA`.
- Gender is 1 = female, 0 = male in all waves (raw ICCS codes: 1 = girl, 0 = boy).
- `parents_univ` uses a wave-specific ISCED rule (see `documents/codebook.md`).
- CivED 1999 currently uses Grade 8 for comparability decisions.

- Keep raw files unchanged in `raw_data/`.
- Regenerate `documents/` and `report/` outputs after changes in processing scripts.
